# Build reliable triage without exposing private workflows

Research checked October 30, 2026. The repository now contains an experimental offline JSON contract, validator, routing evaluator and CLI, documented in [Advisory triage contracts](../triage-contract.md). Training, calibration, prospective qualification and model-backed deployment below remain proposed later phases. This report does not claim that either model achieves 98%, that training is complete, or that a model-backed CI integration has shipped. Public methodology and citations do not transfer licenses for third-party model or dataset assets.

Build a **closed-set review router**, with independently judged labels and a measured cost policy, rather than treating a model's confidence as evidence that code is correct. Train Kev on verified examples; adapt Jev through its documented question and option-description interface because it does not offer customer-specific fine-tuning. Define the 98% target as useful, correct routing across all eligible independent real changes, counting abstentions and failures as misses. Keep defect detection and first-file ranking as separate tasks so their errors remain visible. Public code should provide data contracts, deterministic evaluation and approved-recipe integration; private storage should hold domain rules, datasets, retrieval indexes, prompts and trained adapters. Neither model cards nor synthetic demonstrations establish the requested accuracy. ([TypeSafe models](https://docs.typesafe.ai/models), [Kev model card](https://huggingface.co/jaredpalmer/kev-9b))

**Make the 98% claim precise before creating labels.** For each eligible change, let R be the mandatory review-check set, T the independently adjudicated tolerable set, and P the model's recommendation. A successful routing decision requires a valid recommendation satisfying **R ⊆ P ⊆ T**, within a cost or cardinality policy fixed before evaluation. A check ID should identify the required check and execution mode: running the right check in the wrong mode is not a successful route. The policy must be computable from information available to inference; it cannot be derived from sealed answers or relaxed after failures. Abstention, malformed output, context overflow, refusal, timeout, missing response and omitted candidates count as failures in the primary denominator. Full-matrix fallback protects the workflow but earns no model-accuracy credit. This is the report's proposed estimand, not an observed result.

An independently clean code change can still require review checks. Conversely, an empty recommendation can be correct for an adjudicated no-review change. Gold therefore needs separate fields for confirmed defect status and required review obligations. Tolerable optional checks must be decided before predictions are visible; marking every check tolerable would remove the protection against over-routing. File ranking should accept an adjudicated set of valid first files rather than force an arbitrary unique answer. Report required-review and no-review strata alongside defect and clean strata. Report all-case accuracy and selective accuracy with coverage separately: selective classification deliberately trades coverage for error risk, so a high score on a tiny accepted subset cannot replace the primary target. ([Selective classification](https://arxiv.org/abs/1705.08500), [multilabel metric definitions](https://scikit-learn.org/stable/modules/model_evaluation.html))

For a confidence-supported claim, require both the point estimate and a preregistered one-sided 95% lower confidence bound to reach 98%. With zero errors in n independent decisions, the exact lower bound is 0.05^(1/n): **149/149 yields 98.0095%, while 148/148 yields 97.9962% and fails**. These are calculations, not model results. A hundred perfect decisions are still insufficient: their lower bound is approximately 97.05%. Fix the sample plan before scoring; repeatedly inspecting a holdout and stopping when its interval passes does not preserve that simple confidence interpretation. ([NIST exact-binomial intervals](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm))

Score Kev and Jev separately. Two individual 95% intervals are not a simultaneous 95% guarantee for both. A simple preregistered Bonferroni allocation uses a one-sided 97.5% bound for each model; with zero errors that requires **183 independent decisions per model**. Repeats, several defects in one change, synthetic siblings and option permutations do not increase the independent sample count. For correlated changes, preregister independent family representatives or an appropriate clustered analysis and state the population it estimates. Retain all-PR descriptive results alongside that analysis. A deliberately stratified challenge set with at least 20% controls measures its declared mixture; natural deployment claims additionally need a consecutive prospective real-change stream or justified, preregistered weighting. ([NIST intervals](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm), [grouped and temporal evaluation](https://scikit-learn.org/stable/modules/cross_validation.html))

The following contracts are proposed as separate artifacts. Their separation prevents a convenient training format from accidentally becoming a label-bearing inference request.

| Artifact | Required content | Boundary to enforce |
| --- | --- | --- |
| Inference request | Schema and task revisions; opaque case ID; source/input digests; screened pre-fix diff and context; candidate IDs and descriptions; candidate-generator revision; declared route budget | No repair patch, gold, defect summary, future evidence or paths chosen from the answer key |
| Model result | Exact request digest; model, adapter, prompt and calibration identity; complete probability vectors; selected checks/patterns; ranked file IDs; closed action and reason codes | Candidate-bound IDs only; no generated command or explanation; reject unknown fields, duplicates and nonfinite values |
| Gold record | Exact input digest; defect/clean/unknown status; required, optional and irrelevant obligations; acceptable first files; adjudication state and evidence; rubric revision | Separate from inference; preserve correct labels missing from the candidate list so candidate omissions remain measurable failures |
| Dataset manifest | Input/gold/schema hashes; licenses and provenance; connected family membership; train/validation/calibration/holdout assignments; availability ordering; generation and environment identity; eligibility decisions | Freeze before model evaluation; preserve excluded/disputed counts; do not silently change membership or answers |

Pattern and check probabilities are multilabel quantities and generally need not sum to one. A categorical first-file vector does need its declared normalization. Probability semantics, abstention thresholds and any order-averaging rule belong in the versioned task contract. A hash proves byte identity, not confidentiality, honest labels or sound domain reasoning.

**Use executable evidence to create data, and preserve its limits.** Real-history examples should contain the change that was available to reviewers before repair. Keep the repair and failing-to-passing evidence as gold provenance, not model context. Require a reproducible baseline/candidate comparison and an independent adjudicator; a commit message or model-generated explanation is not a defect label. Defects4J's minimized fixes and reproducible triggering tests provide a useful methodological reference. SWE-smith similarly validates perturbations by comparing test behavior against the original tree. Neither supplies the target project's required-review labels. ([Defects4J bug criteria](https://github.com/rjust/defects4j#the-bugs), [SWE-smith validation](https://swesmith.com/guides/harnesses/))

For specification-based simulations, begin with an approved rule, its preconditions and the implementation under test. Implement an independent reference calculation or relation, then create defective and semantics-preserving twins. A positive example must fail for the intended reason, while its baseline and repair pass. Separate syntax errors, missing dependencies and unrelated crashes from domain defects. Stateful property testing can explore action sequences; metamorphic tests can check a justified relation between executions. Neither method establishes that the chosen relation is valid. Do not assume that splitting, scaling or reordering preserves behavior when rounding, thresholds or tie policies can legitimately change the result. ([Hypothesis stateful testing](https://hypothesis.readthedocs.io/en/latest/stateful.html), [metamorphic testing report](https://arxiv.org/abs/2002.12543), [pytest flaky-test guidance](https://docs.pytest.org/en/stable/explanation/flaky.html))

Keep the root change, repair chain, minimized counterexample, clean twin and all generator/template variants in one connected family. Audit exact and normalized duplicates before splitting. Use time-ordered, family-disjoint training, model-selection validation, calibration and final holdout partitions. Retrieval can use only admitted earlier training families whose labels were available at the query's time. A frozen holdout stays outside prompt construction, example retrieval, taxonomy-example selection and hyperparameter choices. If a final candidate fails, retain the failure and return to development; a revised acceptance claim needs fresh reserved evidence. Temporal and group dependence require different treatment from shuffled row splits. ([Evaluation leakage](https://arxiv.org/abs/2207.07048), [group/time split guidance](https://scikit-learn.org/stable/modules/cross_validation.html))

Every saved evaluation record should show raw row counts, distinct real changes, distinct connected families and the actual independent decision count used for its interval, separately for each partition and real/synthetic/control stratum. Include exclusions, disputed labels, missing candidates, attempted requests and completed responses. A large synthetic row total must never stand in for the independent real-family count required by the primary claim. This report sets the counting contract; it does not publish private corpus counts or imply that sufficient qualified families already exist.

| --- | --- | --- |
| SWE-smith | Procedural mutation and test-validation methodology; selected generic training examples | MIT code and dataset metadata do not settle upstream licensing: the paper lists GPL, LGPL and custom-license repositories. Verify every admitted source revision. ([Paper Appendix A.2](https://arxiv.org/html/2504.21798v2)) |
| CommitPackFT | Generic change representation or retrieval pretraining | Treat commit text as metadata, not verified defects. Verify per-record origin and license; the documented vocabulary includes unknown and non-permissive categories. ([Dataset card](https://huggingface.co/datasets/bigcode/commitpackft)) |
| SWE-bench Verified | External localization and evaluation-harness diagnostics | Keep reference patches/test patches out of prediction inputs; check underlying licenses and disclose unknown pretraining exposure. ([Dataset card](https://huggingface.co/datasets/princeton-nlp/SWE-bench_Verified)) |
| Defects4J | Reproducible defect/provenance methodology | Framework licensing does not replace upstream-project review; language and task differ from review routing. ([Maintainer documentation](https://github.com/rjust/defects4j)) |

([testmon](https://github.com/tarpas/pytest-testmon), [mutmut](https://mutmut.readthedocs.io/en/latest/)) |

Record source URL, exact revision, SPDX identifier, license-file digest, attribution obligations and admission decision per imported record. Start with an explicit permissible-license policy and quarantine unknown/custom cases. Keep public-transfer, historical, simulated and prospective examples in separate reporting strata. Adding thousands of synthetic variants can improve training coverage without supplying thousands of independent real-world observations.

**Train Kev, steer Jev, and measure each change separately.** Kev-9B combines a frozen Qwen3.5 base, rank-16 LoRA and a decision head. Jev uses shared hosted weights; its documented customization occurs through questions and option descriptions, including structured criteria. Thus “training both” means actual local weight adaptation for Kev and development-only optimization of request descriptions, retrieval and calibration for Jev. Pin Jev to a versioned model such as the documented `jev-1.14.0`, and record requested and returned identity. Treat stock Kev v1, stock v2, retrieval-primed variants and a trained adapter as separate experimental arms rather than quietly replacing the baseline. ([Kev card](https://huggingface.co/jaredpalmer/kev-9b), [TypeSafe models](https://docs.typesafe.ai/models), [structured criteria](https://docs.typesafe.ai/primitives/advanced))

A 32 GB inference result does not demonstrate 32 GB training fit. In the inspected Kev trainer, `--dtype bf16` controls computation but leaves backbone weights FP32 by default; `--weights_dtype bf16` is a separate setting. The continuation loader also verifies logical base identity, revision and adapter/head architecture. A local resolver must preserve those identities while reading verified local files. Before a campaign, verify imports and dependencies, then measure one full forward/backward/optimizer step with frozen base weights, batch one, bounded context and checkpointing. The proposed local training path must preserve the released adapter, emit a new checkpoint, and record data/config/source/model hashes. Its memory fit, numerical stability and duration remain acceptance tests, not established facts. ([Pinned trainer](https://raw.githubusercontent.com/jaredpalmer/kev/c9c1f855505336ac32092a5f68305d397f7fcc3e/kev/train.py), [checkpoint checks](https://raw.githubusercontent.com/jaredpalmer/kev/c9c1f855505336ac32092a5f68305d397f7fcc3e/kev/checkpoint.py))

Preserve raw logits or unrounded probabilities and their actual temperature. Jev's Choice confidence is **chance-adjusted maximum probability**, `(p_max − 1/n)/(1 − 1/n)`, not simply the largest probability. Calibration and abstention rules must use a declared statistic and separate calibration families. Positive temperature scaling cannot correct a wrong within-vector ranking. Map all option-order outputs back to stable IDs before averaging; select the number/order policy using development data only. Report ECE with fixed bins, Brier with its normalization stated, reliability support and risk/coverage curves. ([TypeSafe confidence](https://docs.typesafe.ai/confidence), [Kev calibration](https://raw.githubusercontent.com/jaredpalmer/kev/main/kev/calibrate.py), [temperature-scaling research](https://proceedings.mlr.press/v70/guo17a.html))

Freeze GPU, driver, package, kernel, dtype, batch, seed and prompt identity, then repeat the final evaluation in independent clean processes. Identical discrete decisions and probability drift are separate measurements. PyTorch does not promise reproducibility across versions or platforms. Hosted API version pinning likewise is not evidence of bitwise repeatability; the inspected Jev API does not expose a seed/temperature contract. Record failed and empty attempts, disable undisclosed retries, and retain unresolved spend reservations. A timeout is an unknown outcome, not zero usage. ([PyTorch reproducibility](https://docs.pytorch.org/docs/2.8/notes/randomness.html), [TypeSafe API](https://docs.typesafe.ai/api/system-one))

**Keep the reusable harness public and the private method outside its build tree.** The proposed finledgerpoli extension is a data-only advisory boundary: strict JSON validation, canonical hashes, offline scoring and a configured recipe that consumes an already-produced report. Keep the existing model-neutral, approval-based workflow rather than adding automatic executable plugin discovery. Python entry points describe discoverable components; they do not provide a sandbox or authorization. A separate private scorer process can implement the proprietary policy and return only bounded IDs, probabilities and provenance. ([Published finledgerpoli](https://pypi.org/project/finledgerpoli/), [PyPA entry-point specification](https://packaging.python.org/en/latest/specifications/entry-points/))

| Public package and research | Private artifacts and operations |
| --- | --- |
| Generic request/result schemas, validator and metric code | Project specifications, taxonomy meanings, check/mode catalog and candidate mappings |
| Invented fixtures, fake provider transports and failure tests | Confirmed cases, sealed gold, family assignments and retrieval corpus |
| Contract documentation, statistical assumptions and sanitized aggregate methodology | Prompts containing proprietary criteria, trained adapters/head and calibration choices |
| Public-content build policy, artifact inspection and offline wheel tests | Raw diffs, per-case predictions, detailed saved evaluation records and credentials |

Physical separation matters more than a convenient ignore rule. Wheel and source-distribution inclusion rules differ, and cached build metadata can retain files. Build from a clean public-only tree, enumerate both archives against a reviewed content policy, inspect text/metadata/generated resources, and test fictional canaries that represent accidental private inclusion. Test the installed wheel outside the source tree with isolated state, no credentials and network disabled. Check that an sdist alone can build the feature; repeat builds and investigate differences instead of assuming pins imply reproducible bytes. ([Setuptools data inclusion](https://setuptools.pypa.io/en/latest/userguide/datafiles.html), [distribution file selection](https://setuptools.pypa.io/en/latest/userguide/miscellaneous.html), [PyPA downstream packaging](https://packaging.python.org/en/latest/discussions/downstream-packaging/))

Publish through a separately approved exact-revision release using the established PyPI process. Trusted Publishing and attestations establish aspects of upload identity and provenance; they do not establish confidentiality or model quality. If a private adapter later needs packaging, distribute it separately through a dedicated private channel or offline wheelhouse with pinned hashes. Avoid a public optional dependency that fetches private weights, and avoid mixing public and private indexes through `--extra-index-url`, which pip warns can enable dependency confusion. ([PyPI publishing security](https://docs.pypi.org/trusted-publishers/security-model/), [PyPI attestations](https://docs.pypi.org/attestations/), [pip index warning](https://pip.pypa.io/en/stable/cli/pip_install/))

**Integrate advisory output before granting selection authority.** The first CI increment should validate and display a report while preserving every existing required check. Absence, stale source identity, malformed output, abstention or disagreement must leave the full matrix intact and remain visible as an advisory failure. Bind any report to exact repository/base/head, policy, candidates and producer revisions. A model result must not introduce commands, alter required recipes or install a private dependency. No new privileged workflow trigger is necessary to establish this boundary.

Do not execute candidate-controlled source, dependencies, hooks or configuration in a credential-bearing scoring process. Do not expose a private model workstation as a public PR runner. If reports later move between workflows, verify producer/run/event/revision/artifact identity before consuming them as data; validated JSON is still not executable authority. GitHub specifically warns about combining privileged triggers with untrusted checkout and about persistence risks on self-hosted runners. ([GitHub Actions secure use](https://docs.github.com/en/actions/reference/security/secure-use))

| Stage | Evidence required to advance | What it does not establish |
| --- | --- | --- |
| Contracts and corpus | Schema/refusal tests; independently checked provenance; complete gold/catalog separation; family/duplicate/time audit; immutable manifest | Model quality or deployment eligibility |
| Reference experiments | Rules/retrieval and frozen-model arms on identical inputs; candidate recall; separate calibration and validation; full attempt accounting | A trained-model gain |
| Local training | Verified continuation from released checkpoint; bounded successful optimizer steps; new checkpoint identity; validation comparison against frozen baseline | Real-world 98% from synthetic performance |
| Fresh qualification | Prespecified independent real population; all-eligible routing metric and intervals; per-model results; zero observed mandatory/critical omissions; repeated-process checks | Zero true risk or immunity to drift |
| Advisory integration | Exact-request binding; full-matrix fallback; no private build contents or credential exposure; clean installed-wheel and CI conformance checks | Permission to suppress checks or block merges |
| Selection authority | Separate governance approval plus prospective evidence, useful measured efficiency and monitored rollback criteria | Permanent qualification after model/policy/data changes |

The durable asset is the adjudicated decision contract, not one adapter checkpoint. It makes errors diagnosable: an omitted candidate, ambiguous gold, wrong ranking, miscalibrated threshold, stale model or unsafe integration become distinct failures with distinct remedies. Keeping that contract public while preserving domain assets privately lets the generic harness improve without publishing the proprietary method. The 98% target should remain a demanding falsifiable requirement; when evidence falls short, the correct output is a measured gap and a preserved full-review path, not a narrower denominator presented as success.
